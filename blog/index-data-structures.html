从红黑树到 B+ 树：索引的数据结构进化史

2026-03-28 · 10 分钟

数据库索引为什么要用 B+ 树而不是红黑树？本文从二叉搜索树出发，一步步推导出 B+ 树的设计思路，并分析每种数据结构的适用场景。

一、二叉搜索树（BST）

BST 是最基础的树形数据结构：左子树所有节点小于根节点，右子树所有节点大于根节点。平均查找复杂度 O(log n)，但最坏情况下退化为链表 O(n)。

二、红黑树

红黑树是一种自平衡的二叉搜索树，通过颜色约束保证树的高度不超过 2log(n+1)：

  • 每个节点是红色或黑色
  • 根节点是黑色
  • 红色节点的子节点必须是黑色
  • 任一节点到其所有叶子节点的路径上的黑色节点数相同

红黑树在内存中表现优异——C++ STL 的 std::map 和 Java 的 TreeMap 都基于红黑树实现。

三、为什么数据库不用红黑树？

红黑树虽然好，但它有一个关键问题：树的高度。对于海量数据，红黑树的节点数等于数据量，树的高度仍然会增长到 log n。每次查找需要多次磁盘 I/O，而磁盘 I/O 是数据库系统的瓶颈。

关键在于：红黑树每个节点只存储一个键值，一个磁盘块只能加载少量节点。

四、B 树

B 树的核心思想：每个节点存储多个键值，从而大幅降低树的高度。

// B 树节点的简化表示
class BTreeNode {
    keys: [k1, k2, ..., km];        // 有序键
    children: [c0, c1, ..., cm];     // 子节点指针
    leaf: boolean;                  // 是否为叶子节点
}

一个 3 阶 B 树每个节点可存 2 个键，树的高度约为 log3(n)。对于 100 万条数据，红黑树需要约 20 层，B 树只需要约 10 层。

五、B+ 树

B+ 树是 B 树的进一步优化，也是现代数据库的主流索引结构：

  • 非叶子节点只存键，不存数据 — 每个节点可以存更多键，树更矮
  • 叶子节点通过指针串联 — 范围查询时无需回溯，顺序遍历效率极高
  • 所有数据都在叶子节点 — 每次查询的 I/O 次数稳定
-- MySQL InnoDB 默认使用 B+ 树索引
CREATE TABLE users (
    id INT PRIMARY KEY,
    name VARCHAR(100),
    age INT,
    INDEX idx_age (age)
);

-- 主键索引（聚簇索引）：叶子节点存储整行数据
-- 普通索引（二级索引）：叶子节点存储主键值

六、总结对比

  • 红黑树 — 适合内存场景，数据量不大，插入删除频繁
  • B 树 — 适合磁盘场景，每个节点存多个键，树更矮
  • B+ 树 — B 树的进化版，范围查询极快，磁盘 I/O 稳定

选择什么数据结构，取决于你的使用场景和硬件特性——这永远是数据结构与算法设计的第一原则。
