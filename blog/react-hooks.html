React Hooks 原理浅析：useState 与 useEffect

2026-04-20 · 12 分钟

Hooks 是 React 16.8 引入的革命性特性，它让我们在函数组件中使用 state 和生命周期功能。本文将从源码层面解析 useState 和 useEffect 的实现机制。

一、Hooks 的核心：链表

React 在函数组件内部维护了一个 hooks 链表。每次调用 hook（如 useState）时，React 都会创建或读取链表中的一个节点：

// 简化版 Hook 节点结构
type Hook = {
    memoizedState: any,    // 当前状态值
    next: Hook | null,      // 指向下一个 hook
};

// React 内部维护的当前 fiber
let currentlyRenderingFiber = ...;
let workInProgressHook = null;
let hookIndex = 0;

为什么 Hooks 不能放在条件语句中？因为 React 依赖调用顺序来匹配每次渲染中的 hook 和链表节点。如果条件执行导致某次渲染少调用了一个 hook，链表就错位了。

二、useState 的实现

function useState(initialState) {
    // 获取当前 hook 节点
    const hook = getHook(hookIndex++);

    if (hook.memoizedState === undefined) {
        hook.memoizedState = typeof initialState === 'function'
            ? initialState()
            : initialState;
    }

    const dispatch = createDispatcher(hook);
    return [hook.memoizedState, dispatch];
}

当调用 setState 时，React 会将更新放入一个队列中，并在下一次渲染时重新计算状态。如果多次调用 setState，React 会批量合并更新。

三、useEffect 的实现

function useEffect(create, deps) {
    const hook = getHook(hookIndex++);

    const prevDeps = hook.memoizedState;

    if (areDepsEqual(prevDeps, deps)) {
        return;  // 依赖没变，跳过
    }

    // 在浏览器绘制后执行副作用
    scheduleEffect(create);
    hook.memoizedState = deps;
}

关键点：

  • 依赖比较 — 使用 Object.is 逐个比较依赖项
  • 执行时机 — useEffect 在浏览器完成布局和绘制后异步执行
  • 清理函数 — 如果 create 返回一个函数，React 会在重新执行 effect 前或组件卸载时调用它

四、为什么 Hooks 改变了 React 的编程范式

  • 逻辑复用 — 自定义 Hooks 让状态逻辑的复用变得简单，不再需要 HOC 或 Render Props
  • 关注点分离 — 你不再需要按照生命周期拆分代码，而是按照功能模块来组织
  • 减少心智负担 — 不再需要频繁地在类方法之间切换注意力

五、总结

理解 Hooks 的原理并不复杂，关键在于记住：React 通过链表的顺序来匹配每次渲染中的 Hooks 调用。这个设计简洁而优雅，也解释了为什么 Hooks 有"不能放在条件语句中"这条规则。
